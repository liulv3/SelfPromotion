# 产品经理 C：科研管家、日报与周报 PPT

设计日期：2026-10-22。职责为目标 4（每日发现、进度监督、科研日报）和目标 5（外部 PPT Skill、可编辑周报）。这是产品方案；本轮没有建立定时任务、访问个人文献库或运行项目。以下验收是拟定目标，未经实测。

## 核心观点

把科研管家做成“每天交付一个可处理的短名单、如实整理已发生的研究活动、将确认过的知识变成汇报材料”。推荐数量不代表科研进展，AI 解读任务完成不代表人已理解。默认自动完成低风险草稿，人工确认只集中在正式收藏、关键技术关系和对外宣称的研究结论。

系统必须区分：抓到、正式收藏、用户已读、用户自评理解、实验复现。它们是不同事实维度，不是一条由 AI 自动推进的流水线。“没有活动记录”只说明未记录进展，不能解释成用户没有做科研。

## 1. 兴趣与发现模块

研究兴趣配置含当前研究问题、技术主题、种子论文、纳入/排除关键词、关注作者/会议/期刊、可选来源、研究阶段和每日预算。用户可用自然语言建立配置，但实际执行的查询、过滤范围和偏好版本必须可见、可改、可回滚。关键词偏好和当前实验任务分开，避免一篇临时阅读论文改变长期方向。

每日流程：

1. 按配置查询来源，记录来源、查询、时间范围、最后成功游标与响应状态。
2. 用 DOI、arXiv ID 及版本等做身份归并；模糊匹配只生成疑似重复，不能误合并并删除条目。
3. 全部发现进入候选池，筛选和排序生成可调短名单，不直接污染 Zotero 正式文献库。
4. 先做标题/摘要级筛选；只对短名单进行全文速读；精读、数学推导和跨论文研究由用户需求或明确的预授权预算触发。各层标记实际读取范围。
5. 给出“为什么推荐”“对应当前哪个问题”“与已收藏论文的关系候选”。仅凭摘要不能评价全文实验或宣布技术继承关系成立。
6. 用户选择收藏、稍后、相关/无关或暂时略过；“略过”不自动等于反感这个研究方向，“收藏”也不等于高质量结论。反馈更新可解释的偏好配置，不暗中改写长期目标。

候选默认自动获得元数据、来源、推荐理由、机器草稿摘要和去重关系；收藏/忽略支持批量操作。可以将“收藏 + 确认一句话回忆卡 + 选定技术位置”组合成一次操作，但主干关系仍需显式确认。用户无需审阅每一条摘要才可以看日报。

检索覆盖不是“搜遍所有文献”。页面展示启用来源、成功来源、失败来源、本次时间窗、材料可访问性和短名单筛选范围。状态至少区分：成功有新结果、成功无新结果、部分失败、全部失败、尚未运行。失败的来源不推进成功游标；允许补抓并去重。预算耗尽、付费墙、缺全文、限流和解析失败各自可见，不能以空列表冒充没有新论文。

默认日程时区为 Asia/Shanghai，可修改。仅本地部署且电脑离线时显示“未执行”，上线后按策略补跑；只有明确部署了常开任务执行端，才承诺日常按时执行。补跑可合并多个日期的候选，避免重复通知。通知由用户配置；默认仅有可处理短名单、关键失败或用户要求的进度提醒时通知。

## 2. 真实活动账本与适度监督

账本保存事件时间、操作者/来源、对象、明确动作、用户说明和相关产物，而不是根据鼠标停留时长猜测进展。

| 记录 | 可以说明什么 | 不能自动说明什么 |
|---|---|---|
| 文献被抓到、推荐、收藏 | 发现或归档动作 | 用户已读 |
| PDF 打开、批注、零散笔记 | 阅读活动已发生 | 已经读完、理解正确 |
| AI 解读完成 | 一份解读产物可查看 | 人已读、已掌握 |
| 用户明确标记读完 | 用户声明完成阅读 | 结论已验证 |
| 用户确认理解笔记、自评、解释问题结果 | 特定范围的理解记录；保留类型 | 客观认证用户完全掌握 |
| 关联代码/参数/环境/数据/指标的复现实验 | 可检查的实验产物及用户确认 | 复现必然成功或适用于不同条件 |

“监督”以用户设置的研究目标和下一步为依据，提供轻量自评与阻塞记录，例如本周要验证的假设、需要补的基线、未解决问题。默认不以阅读数量排名或以连续打卡惩罚。无记录时可询问是否补记，日报显示“未记录”，允许用户更正历史记录。实验失败也是真实进展，应保留失败结果和下一步。

## 3. 科研日报与统一内容包

日报使用同一个结构化 ReportBundle 生成页面、邮件草稿或后续周报材料，不能每个输出重新检索并编写新事实。建议包含：

- 今日候选短名单：各论文一句话、推荐理由、材料范围、是否已有全文、收藏入口。
- 今日研究活动：来自账本的阅读、确认知识、实验、问题与阻塞；零记录明确标记。
- 技术网络变化：本日已确认的新节点/关系；未确认建议单独展示。
- 下一步建议：最多几个与当前问题有关的动作，注明理由、所需材料和成本档位；它们是建议，不是已经完成的工作。
- 检索与执行情况：来源覆盖、失败/遗漏、预算、补跑与待处理任务。

ReportBundle 保留报告时间窗、配置版本、来源运行记录、活动事件 ID、paper_id/document_version、claim_id/revision、evidence 引用、确认状态和材料范围。报告生成后形成不可变快照；用户更正知识时可生成新报告版本，而不是悄悄改变已汇报的旧版本。

确定性成果段默认只使用用户确认或已核验的项目；自动摘要在“机器草稿/候选发现”区可直接有用。未确认数学推导、作者思想重建、争议结论可以进入明确标记的讨论区，不能在汇总时丢失限定词。

## 4. 周报与可编辑 PPT

流程为“选时间窗与受众 → 复用 ReportBundle 和活动账本 → 产生故事线与逐页大纲 → 检查关键结论 → 渲染可编辑 PPTX → 渲染预览检查”。汇报可包括研究问题、阅读得到的关键认识、技术主干变化、实验与失败、当前阻塞、下周计划和参考资料。

PPT Skill 接口输入结构化内容包、模板、受众、时长与页面约束；输出逐页计划、可编辑演示文件、预览和检查报告。原生文本框、表格、图形和图表应保持可编辑；复杂公式/原论文图允许作为图片，但应标记并附原始公式文本或来源。每页保留 claim_ref 和来源清单，可通过备注/附录返回原文版本及页码。

PptxGenJS 可作为可替换的 PPTX 输出器。Paper2Slides 的分阶段过程可参考，但图片生成和 PDF 样例不能证明它能输出可编辑 PPTX。图像生成用于辅助插图，不承担数据、结论和公式的事实来源。

检查分为两类：内容检查确认结论来自所选快照、假说/未验证项保留标签、数值单位一致；版式检查验证文件能打开、没有文本溢出/遮挡、字体与公式显示正常、文本和图表实际可编辑。AI 审阅意见只能辅助，不能代替实际导出渲染。若生成失败，仍保存大纲和内容包以便重试，不让用户重做阅读与确认。

外部 Skill 采用声明输入/输出、所需工具、预算、版本和权限的契约；只授予任务所需资料。日报检索和 PPT 渲染不自动获得修改 Zotero 或向外发送汇报的权限。此处是产品将来的能力边界，本轮未创建任何发送任务或自动化。

## 5. 与另外两位产品经理的讨论结果

已分别与 PM A（文库/技术谱系）和 PM B（解读/Skill）进行了实质问答与回应，两个议题均已收敛，没有继续循环。

与 PM A 对齐后作出两项修订：第一，只有明确“读完/完成”的用户动作或记事才推进已读，零散笔记仅计活动；第二，新论文版本自动关联同一身份并成为待检查版本，不替换旧版已确认知识。报告锁定原文与知识版本，显示“已有新版”；若新证据影响旧结论，标记需复核，不重写历史报告。双方同意一次确认可同时完成收藏、回忆卡与技术位置选择，降低操作负担。

与 PM B 对齐后，采用 ReadingRun / KnowledgePatch 契约：run_id、skill_id/version、paper_id/document_version、requested_scope、inspected_scope/material_scope、output_status、claims、evidence、checks、known_gaps、recommended_followup、cost、termination_reason。claim 包含类型、文本、证据、假设、限制；PPT 引用不可变 claim 修订。解读完成仅产生 AI 活动，不推进人的已读/理解/复现。后续精读推荐必须给理由、预期价值、所需材料与成本档位，不能自动无限升级。

## 6. 给 CTO / 项目经理的实现拆分与验收建议

| 能力 | 首版边界与依赖 | 难点及可靠性要求 |
|---|---|---|
| 发现与候选池 | 先选择少量学术来源，完成去重、反馈、短名单和状态展示 | 来源覆盖/元数据质量有限；检索日志、游标、幂等、预算、补跑必须可见 |
| 进度账本 | 手工简记 + Zotero/解读任务产生的明确事件 | 不把活动推断成理解；修订和来源可追踪；数据缺失与没有进展分开 |
| 日报内容包 | 复用文库身份、证据模型、活动事件 | 机器草稿与确认知识隔离；版本锁定，未知不能被写成事实 |
| 周报 PPT | 固定少量模板与一种可编辑输出器 | 内容来源、数值、原生可编辑性与最终渲染都要验；不可用整页图片冒充编辑能力 |
| Skill 扩展与日程 | 复用 PM B 工作流引擎，单次/定时共用运行模型 | 失败恢复、限额、停机补跑、工具权限、无新证据终止；本地并非默认 24 小时在线 |

首版应先跑通“发现候选→收藏/读书记录→确认少量知识→日报→可编辑周报”闭环；自动理解评价、复杂推荐学习和多源大规模抓取放后。复用候选为 GPT Researcher 的可拆分检索流程、PptxGenJS 输出器和 LangGraph 状态执行；ArxRec 仅参考反馈思路，当前没有核验到许可证，不能直接复制其代码。选型事实与局限详见 ../research/2026-10-22/github-projects.md 和 ../research/2026-10-22/blog-practices.md。

建议用用户真实的已读论文与一周活动样本验收：同日重复运行不会重复收藏；来源断网显示部分失败而非零发现；只有摘要时不出现全文级结论；AI 解读成功不增加已读数量；无记录不编造进展；新版论文不覆写旧报告；确认结论每条能回到相应证据；PPT 实际能打开、编辑且无明显溢出。目标值与费用在小样本试点后再决定，当前不承诺正确率、召回率或固定每日成本。

交 CTO 的未决实现项：来源集合应由实际科研方向决定；本地优先与常开执行端需在部署阶段选择；可编辑公式的技术方案应以真实样例试验后确定。这些不妨碍当前模块边界与首版闭环定稿。
