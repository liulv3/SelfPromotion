# 项目经理 C：工作台、发现、报告与部署

> 首轮实现参考（2026-10-22）：真实活动、报告快照与输出验收要求继续保留；自建 Vite 工作台、旧目录和 SQLite 部署已被调整。以 [当前架构](../architecture/current-architecture.md)、[目录规范](../development/repository-layout.md)及 [ADR 0002](../decisions/0002-open-notebook-base.md)为准，旧工期不直接沿用。

2026-10-22。依据 CTO 产品契约及两份检索报告；本轮为工程方案，未安装、创建自动化或生成 PPT。观点：先把一个真实研究主题的“发现—阅读活动—确认知识—日报—周报”闭环做可靠，工作台展示真实状态，所有执行只走 B、正式数据只走 A。

## 1. 模块、界面与单一职责

| 模块 | 首版实现与接口 | 难度/主要不确定性 |
|---|---|---|
| 工作台 | React/TypeScript + Vite；首页短名单、文库/证据侧栏、技术树、解读任务、研究日志、日报/周报六入口。打开原文交 Zotero，技术图使用 A 的树投影/跨枝边；所有任务展示 B 的统一状态、材料范围、费用和缺口 | 中；难点是让复杂状态可理解，避免用户被迫逐条审阅草稿 |
| 候选与偏好 | 首版一个可配置发现源，依学科选 arXiv 或适合的其他来源；明确查询/排除词/时间窗/每日上限。DOI 等身份判定交 A；相关/无关、稍后、收藏分别记录，先用可解释规则排序，偏好变更版本化 | 中；来源覆盖、访问许可、配额和元数据质量不可保证；不承诺全领域全量或无限免费 |
| 真实活动账本 | C 定义事件语义，经 A 的 append API 写共享领域库。打开、批注、AI 完成只算活动；读完由用户声明，理解保留自评类型，复现附产物。支持补记、更正事件及阻塞记录 | 中；关键是避免把行为推断成科研成果 |
| 发现日程 | C 保存日程、时区、触发 outbox、每源成功游标；提交 B 的统一任务。B 拥有执行状态、重试、租约、检查点。来源成功/无新结果/部分失败/失败/未运行分开 | 中高；离线补跑、部分窗口、幂等与预算是主要工作量 |
| ReportBundle | 从 A 的一致快照创建不可变内容包；锁活动 ID、论文版本、claim 修订、证据、主干视图、配置和检索运行、实际材料范围。确定成果/机器草稿/讨论假说分区；历史只能创建新修订 | 中高；快照跨数据域及证据保留比文字生成更难 |

建议目录：`apps/workbench`；`services/domain/{activity,discovery,reports}`（A 的同一领域服务内）；`services/execution`（B 维护）；`packages/contracts`；`renderers/pptx`；`deploy/local`。模块边界用于协作和测试，不意味着每项都要独立服务。工作台调用 FastAPI 模块化单体，领域数据先用 SQLite WAL；不另建知识库、活动库或 Agent 调度器。

## 2. 复用决定与部署拓扑

**二选一采用 AnythingLLM 做有期限的功能原型。** 它的现成文档问答用于 3—5 个工作日验证检索、引用和模型接入；不同时部署 Open Notebook，不把 AnythingLLM 的定时任务或 Agent 流程变成第二执行入口。正式身份、证据、技术谱系、确认状态从第一天就在 A 的自有模型中；原型只保留可丢弃的对话/索引，接入前先验证必要 API 和引用回传能力。没有合适接口时停止扩展原型，不 fork 整站去维护另一套领域模型。正式工作台启用即撤下原型外壳，仅保留确实减少维护成本的窄适配组件。原型可评估用户体验，不能证明学术答案准确。

本地首版：`浏览器工作台 → FastAPI/A 领域层 → 本地 SQLite + 获准缓存/产物目录`；B 的后台 worker 在同机运行，调用模型服务、来源适配器及 Node PPT 渲染器；Zotero Local/Web 由 A 按实际能力连接。API 默认本机访问，密钥不写进报告或数据库导出。提供固定版本环境、迁移/回滚说明和一键启动脚本；容器方案作为熟悉 Docker 用户的可选部署，不把 Windows 用户使用容器作为前置条件。

本地电脑关机时页面须显示“未执行”，上线后显式补跑。后续确需准时执行，再将**同一个**领域服务/B worker/调度触发器迁到常开端，并迁移 Postgres；不保留两个写入主库。常开端无法直接访问用户电脑的 Zotero Local，应使用获授权的 Web 接口与可访问附件，或稍后实现明确的本地同步桥。资料不可达时显示实际材料范围和新鲜度；可用旧缓存时注明旧版，不能宣称已经检查最新全文。

## 3. 与 A/B 的实质讨论及收敛

**A 挑战报告历史稳定性，C 反问跨分钟生成的一致性和附件清理。** 修订为 A 在一次读事务捕获 `commit_sequence + ledger_watermark + 各对象修订`；用户可见 cutoff 是时间，准确边界是持久序号。活动语义归 C，存储经过 A，共享一个序号；迟到活动只进入下一报告或新修订。创建快照即 pin 所需版本/证据及获准留存的附件，MVP 不自动清理被报告引用对象；没有留存条件时只 pin 元数据/合法片段，不能保证未来外站仍可访问。`material_level` 与 `freshness/availability` 分开，避免用一个枚举混合“读到什么”和“是否最新/可达”。

**B 挑战部分任务是否进入报告，C 反问离线补跑与重复付费。** 确认 `queued/running` 不进入确定成果；`partial` 只取已持久化产物并保留实际范围与缺口，来源失败仅报告状态。C 通过 `submit_run(idempotency_key, task_spec, snapshot_id, budget)` 提交任务，不自建重试引擎。离线补跑仅合并未领取触发；running 的任务说明不变。B 返回每源 `processed_window/completeness/receipt`，C 仅在完整窗口且候选入库回执成功时 CAS 推进成功游标，部分成功保留未处理范围。摘要缓存按材料版本/hash、模板/模型/配置及范围复用；但远端已计费而本地响应未落库的崩溃窗口可能重复收费，标 `uncertain_external_call`，优先查提供商 request_id，否则在预算内显式决定重试。`paused_budget` 不自动重投。两组议题各完成挑战、回应与修订，无需继续循环。

## 4. 分期、工期与质量门槛

团队假设：3 名熟悉相应栈的全职工程师分别负责 A/B/C，另有研究者每周约半天到一天参与样本与语义验收、共享测试/设计支持约 0.5 人；不是单人兼职估计。整体可讨论的量级为 **8—12 周形成受限试点**，须由 CTO 合并 A/B 风险后确认；C 责任模块约 **5—7 人周**，依赖 A/B 的契约与最小实现，不能与其他经理的人周机械相加。

1. **接口与试验，首 1 周**：固定契约、真实样本、原型取舍及 PPT 模板试导出；及早暴露附件访问、复杂公式和渲染环境问题。
2. **基础闭环，约第 2—5 周**：随 A/B 上线工作台、候选池、手工活动、只读证据及任务状态；技术谱系写入/审阅由 A，解读由 B，C 不绕过。
3. **管家与报告，约第 5—8 周**：一个来源、触发/补跑、ReportBundle、日报、一个固定周报模板；不同时做多源大抓取和自由团队编辑器。
4. **可靠性试点，约第 8—12 周**：真实样本回放、断网/崩溃/限额测试、PPT 实际渲染与编辑、备份恢复；常开部署为后续可选阶段，需再按访问与运维条件估算。

验收以约 20 篇代表性论文和一周活动为起点：重复触发不重复正式对象；失败源不推进成功游标；AI 完成不增加人的已读；无记录不编造进展；缺全文不产出全文级断言；旧报告在论文换版、关系修改后仍保持原内容并可回溯；补记只产生新报告修订。PPT 正文、表格、图表使用原生对象；复杂公式/原论文图允许图片但附公式文本或来源。检查 PPTX 对象结构之外，还要在选定目标软件实际打开、渲染并抽样编辑，验收没有明显溢出/遮挡、单位一致、每页关键结论可追溯且假说标签保留；仅能导出文件或得到截图不算通过。

质量不能由“多个 Agent 同意”担保：用用户真实样本核查证据、记录人工修正时间/成本与失败原因，再决定是否扩大自动化。费用主要来自短名单数量、全文解析/视觉页数、模型上下文、审阅轮次与未来常开端；先摘要筛选，再对少量全文处理，报告复用快照，不为每张幻灯片重新生成一轮科研事实。保留预算和阶段产物，比承诺固定低价更可信。
