# 新会话与渐进式上下文

根 `AGENTS.md` 是唯一项目核心指令入口，不保留其他拼写的兼容文件。标准发现行为和资料来源见 [方法调研](methods-research.md)。

## 读取路径

1. 自动载入或显式读取核心约定；新窗口接着读 [开发交接](../HANDOFF.md)、[状态](../STATUS.md)与[索引](../INDEX.md)。
2. 从用户目的选最窄路径。例如“修复 Zotero 同步”先读当前架构与文献模块，不先读 PPT 或全部研究报告。
3. 只在需要证据、接口或历史取舍时展开下一层；记录本轮实际采用的决策，不把未读文档当作已知。
4. 改动代码前读取对应模块 README、当前接口和验收说明；模块细节不另建重复的核心指令入口。
5. 结束时写明完成内容、真实验证和下一步；复杂持续任务可在 `docs/development/work-items/` 保存短任务记录，没必要为每次小改动创建文件。

## 防止信息漂移

优先级为用户当前明确指令 → 项目核心约定与对应模块说明 → 当前已采纳 ADR 与当前文档 → 历史讨论/调研。证据冲突须明确指出，不因旧方案篇幅较长就优先它。索引不是自动上下文加载器；上述按需读取是执行约定。

交接文档保存恢复背景、下一步做法和阶段依赖，不取代状态或架构正文。`STATUS.md` 是最新事实入口；`HANDOFF.md` 若与新状态冲突，应更新交接内容而非回退新进度。只维护 `docs/HANDOFF.md` 一份当前交接，不在根目录或各子目录复制同名进度文件。

当前架构改变时同步更新当前文档、状态与相关索引；旧决策标为被替代，保留原因。个人论文笔记和运行日志放被忽略的数据目录，避免被误当项目开发规范。只有重复稳定的开发操作才值得提炼为 Skill；产品自己的阅读/PPT Skill 与开发助手的指令不是同一类文件。

## 文档覆盖什么，不能保证什么

当前文档覆盖产品目标、模块职责、拟定数据契约、架构选择、代码/资料归属及下一步验证；应用尚未引入，所以没有真实安装、接口行为或运行手册可以宣称完备。随着实现，应以实际代码和验证结果校准文档，而不是把设计当作已实现功能。

| 发生的变化 | 同次提交需要更新的权威位置 |
|---|---|
| 用户能力、范围或验收标准改变 | 对应 `docs/product/` 文档 |
| 模块职责、数据流或部署方式改变 | 当前架构；重大取舍另记 ADR |
| 新增模块、启动参数、接口或配置 | 模块 README/对应接口文档；只记录实际验证过的命令 |
| 新增、迁移或废弃开发文档 | `docs/INDEX.md` 或它链接的模块目录；修复引用，过期正文标记替代项 |
| 完成任务、出现阻塞或验证结论变化 | `docs/STATUS.md`；保留当前摘要，不复制整段开发流水账 |
| 阶段切换、下一步接手方式或依赖改变 | `docs/HANDOFF.md`；链接状态与权威正文，避免重复完整进度 |
| 日常导入论文、生成报告 | 应用的数据记录与产物清单；不逐次修改项目开发文档 |

每个主题只有一个当前正文，其他地方引用它；不持续新增“最终版2”“最新最终版”等副本。一次小修改不新建一份总结文件，Git 已保存改动历史。

`scripts/check_repo.py` 检查本地链接、`docs/` 文档能否从索引逐层到达、根目录 Markdown 归属及私人数据跟踪边界。它不能判断说明是否符合代码，也不能自动阻止用户在文件系统中任意放置资料；提交前必须运行检查，并审阅本次行为变化对应的文档。实际使用阶段还需由应用统一生成论文版本目录、运行 ID 和产物清单，该能力目前尚未实现。
