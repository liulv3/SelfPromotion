# 当前架构方向

更新：2026-10-23。状态：**待试点的设计，尚无运行中的应用**。选择与退出条件见 [ADR 0002](../decisions/0002-open-notebook-base.md)。本页替代旧方案的默认技术栈；具体接口会在引入锁定版本后校准。

## 一套工作台，一个正式知识写入口

```text
用户 / Zotero 原库
    │ 阅读、批注、只读导入
    ▼
Open Notebook 工作台（保留 Next.js/React）
    │ 复用资料、笔记、搜索、模型配置、任务界面
    ▼
FastAPI（保留上游后端，增加科研领域 API）
    ├─ 上游 notebook / source / note 等通用能力
    ├─ 科研领域模块：身份与版本 → 证据 → 主张与技术关系
    │                 → 审阅/确认 → 活动记录与报告快照
    └─ 统一作业入口 → 有预算的解析、解读、检索、汇报工作流
          ├─ Zotero / 文献来源适配器
          ├─ 解析器、模型和证据检索器
          └─ SlidePlan → PPTX 渲染器
    │
    ▼
SurrealDB + 原文/产物文件存储
    ├─ 上游对象与自有领域对象保持明确边界和关联
    └─ 个人数据、缓存、报告默认不入源码 Git
```

以上框表示职责，不要求拆成微服务。数据库技术优先沿用 SurrealDB，自有对象通过独立 schema/repository 管理；不把聊天文本、向量索引或运行 checkpoint 当作正式技术知识。

## 模块职责与复用方式

| 部分 | 基底提供什么 | 本项目新增什么 | 质量边界 |
|---|---|---|---|
| 文献工作区 | 工作区、来源、笔记、搜索及模型设置 | Zotero 只读桥接、稳定身份、重复导入和附件版本关联 | Zotero 原件不被改写；来源实例、论文身份和文件版本不能混用 |
| 技术知识 | 展示与编辑入口 | 一句话记忆卡、多父技术关系、主干视图、草稿补丁和确认 | 每条重要关系关联证据及修订；引用/相似不直接当作继承 |
| 多模式解读 | 转换/模型调用及已有执行基础 | 精读、推导、思路重建的声明式 Skill 与审阅流程 | 原文陈述、系统推导、思路假说分开；工具权限、预算和停止条件明确 |
| 科研管家 | 来源与作业入口 | 文献源增量检索、候选反馈、真实活动账本、日报 | 获取、阅读、理解、复现分开记录；未完成和未检查不能被总结成完成 |
| 周报与 PPT | 内容入口、作业基础 | 固定报告快照、SlidePlan、模板与可编辑 PPTX | 从快照生成；校验引用与数字，打开/渲染/抽样编辑后才算输出验收 |

产品的声明式 `skills/` 与开发时由 Codex 使用的 Skill 不等同；本轮没有自动安装或执行外部 Skill。任意 Skill 也不能直接改正式知识，只能通过受约束的工具和确认接口提交。

## 稳定的领域边界

最小对象链为 `SourceInstance → Paper → DocumentVersion → Evidence → Claim/Relation → Revision/Confirmation → ReportSnapshot`。它们是拟定契约，尚无建表实现。

- 文档版本固定文件散列与解析版本；证据保存定位方式，不能仅存一段脱离来源的摘要。
- 技术关系允许多个来源/父节点，树只是选择主干后的视图；保存关系类型、证据和确认状态。
- AI 输出先形成候选补丁；确认接口拥有正式领域写权限，保存前置版本以拒绝旧任务覆盖新结果。
- 作业中断和重试必须幂等，执行状态与领域提交明确衔接；不能假定上游已有任务功能便已满足这些语义。
- 报告快照固定选定的知识修订、证据和真实活动；后续编辑不静默改变已生成的周报。
- 提供带 schema_version 的导出清单及文件校验；数据库备份和可迁移数据导出分别验证。

## 接入顺序与目录

先在 `apps/notebook/` 引入锁定上游，保持其内部结构。`packages/research-core/` 保存自有领域逻辑和适配接口，最终由同一 FastAPI 加载；`packages/contracts/` 只共享必要 schema。`renderers/pptx/` 通过单一作业入口调用。上述目录目前仅有说明或为空，未建可运行包。

第一步验证 Zotero → 版本化证据 → 简介/关系 → 确认/快照。先评估基底已有解析能力，缺口明确后接 Docling；PaperQA2 与基础检索在同一评测集比较后再决定。PptxGenJS 可作为后期输出适配器，避免把 Paper2Slides 的图片/PDF 输出误当可编辑幻灯片。

部署时必须实测本机 Zotero 与容器后端的连接、附件访问和路径映射。不能默认容器的 localhost 就是 Windows 的 Zotero，也不能用数据库备份替代原文文件备份。默认的本地数据职责见 [目录规范](../development/repository-layout.md)，现有逻辑图见 [模块图](../assets/architecture/overview.png)；逻辑图不代表本轮已部署的新技术栈。
