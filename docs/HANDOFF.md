## 先确认当前处境

SelfPromotion 是个人科研知识工作台。用户希望保留 Zotero 的阅读能力，在其上增加论文记忆卡、技术谱系、多模式深度解读、每日文献发现/科研日报和可编辑周报 PPT。完整需求见 [产品范围](product/scope.md)。

**当前仍是方案与仓库建设阶段，没有可运行产品。** 已完成两路项目检索、三产品经理与三项目经理的讨论、CTO 汇总、基底比较、逻辑架构图、目录规范和仓库检查工具。原始结论与出处均已入库；不用重新召集同一轮团队。`apps/`、`packages/` 等目前只有目录说明或预留位置，不能当作已实现功能。

用户已指定个人仓库：[liulv3/SelfPromotion](https://github.com/liulv3/SelfPromotion)。`origin` 使用 `https://github.com/liulv3/SelfPromotion.git`，主分支为 `main`，现有历史应保留。根目录只有一个 `AGENTS.md`；用户已澄清此前其他拼写是输入错误。源码与开发资料同步 Git，私人论文、笔记、运行库和生成报告按既有规则排除。

## 下一项开发任务：验证基底通路

本轮整理与上传不包含应用集成。后续用户继续开发时，先执行下列试点，避免一次引入所有候选项目：

1. **固定上游。** 选择 Open Notebook 的明确 commit，核验其安装要求与许可证；以可审计导入方式进入 `apps/notebook/`，保留上游结构，不创建嵌套 `.git`。记录来源、版本、改动挂接点和升级办法。
2. **跑通原有能力。** 在目标 Windows 环境完成启动、来源导入、搜索/转换、作业查询和源文件取回。先记录实际命令与结果，再写运行说明。
3. **实现最小科研链。** Zotero 只读映射 → 固定文档版本 → 一条可定位证据 → 简介 → 一条技术关系 → 人工确认 → 报告快照。先少量样本，再扩到约 20 篇已读论文。
4. **验证再扩展。** 检查重复导入与中断重试不重复提交、换 PDF 不改旧证据、后续编辑不改旧快照、备份恢复和结构化导出可用。通过后再展开深度解读、每日发现和 PPT。

3–5 个工作日是试验时间盒，不是完整产品交付承诺。回退条件和逐项通过标准由 ADR 维护，本页不另写第二套标准。

尚未落实的输入：用户学科/研究主题、Zotero 试点集合与样本、模型端点/预算、目标环境的运行方式。不能默认所有学科都用 arXiv；模型凭据不得进入 Git。先推进不依赖这些输入的上游检查和公开/合成样本验证，需要真实数据时再取得具体范围。容器访问本机 Zotero、附件路径和文件权限必须实测。

## 每个新窗口的最小操作

1. 读取根 `AGENTS.md`、本页和 [当前状态](STATUS.md)，再从索引选择本次任务相关的 1–3 份文档。
2. 查看真实 Git 状态与远端，保留已有未提交修改；不要根据旧会话的提交号推断当前 HEAD。

```text
git status --short --branch
git remote -v
git log -5 --oneline
python scripts/check_repo.py
git diff --check
```

目前只有仓库文档与边界检查可执行，没有应用启动/测试命令。检查成功不代表科研解释正确或软件已可运行。本机首次连接曾遇到过期代理设置，已按系统现用地址修正本仓库的本地 Git 配置；其他机器若连接失败，应核对实际代理与认证，不能照抄本机地址或修改全局配置。

- 实现或接口改变时同步对应当前文档；阶段或下一步改变时更新本页和状态，新增文档必须能从索引到达。不要新建根目录交接文件或不断生成“最终版”副本，详见 [文档维护约定](development/context-loading.md)。
