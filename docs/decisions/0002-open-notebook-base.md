# ADR 0002：优先扩展 Open Notebook 原栈

日期：2026-10-23。状态：**已采纳为试点方向，正式采用须通过集成验证**。本轮未引入或运行上游源码。

## 背景与替代范围

本项目需要文献工作区、模型配置、来源展示、搜索、笔记和任务界面，也需要现成产品缺少的 Zotero 身份映射、版本化证据、技术谱系、审阅与科研报告。前一轮将 AnythingLLM 视为快速原型，并提出自建 Vite/FastAPI/SQLite。重新核验后，Open Notebook 的研究工作台能力和 Python API 更贴近长期扩展目标。

SQLite 是之前的设计选择，不是用户约束，不能用它反过来排除适合复用的基底。本决策替代 [首轮架构](../architecture/overview.md) 和 [平台方案](../engineering/platform.md) 中的默认自建技术栈；其中身份、证据、确认、幂等和版本契约继续作为实现要求。旧工期估算不直接沿用。

## 决定

1. **先选 Open Notebook 一个完整应用作为基底**，保留 Next.js/React、FastAPI、SurrealDB 及上游内部目录，锁定 commit 后再引入。本仓库预留 `apps/notebook/`，保持一个 Git 主仓库，保留上游许可证和来源记录。
2. 在同一后端中新增独立科研领域模块，通过明确接口关联 source/notebook。自有对象包括论文身份/版本、证据、主张、技术关系、确认记录、活动和报告快照。代码隔离不意味着另建一套应用或第二个正式知识数据库。
3. 优先适配 SurrealDB 的持久化能力，并复用上游作业入口；已有 LangGraph 依赖用于受控工作流。SQLite checkpoint 即使存在，也只是执行实现，不承担第二套正式领域知识。
4. 专用能力通过组件或进程接口接入：Zotero 只读适配器、可替换解析器、可选证据检索器及 PPTX 渲染器。不能把多个完整应用的数据库、界面和总调度器并排运行便称为合并完成。

完整比较、评分与原始链接见 [项目基底评估](../research/base-project-ranking.md)，当前边界见 [当前架构](../architecture/current-architecture.md)。

## 收益与代价

预计可以复用通用工作区、资料/笔记、模型配置、搜索、转换及任务界面，减少重复建设。此判断基于公开 API 与源码结构，**没有实装计时，不能量化节省多少周**。

代价是 SurrealDB 的部署/恢复、既有来源及任务模型的耦合、以后合并上游更新，以及 Windows、容器与本机 Zotero 之间的路径和网络适配。新增逻辑集中于领域模块与少量挂接点，避免在 fork 时同时替换前端、数据库和执行系统。

## 3–5 个工作日的通路试验

这是暴露集成风险的时间盒，不是承诺五天交付完整系统。准备约 20 篇已读论文；先以少量样本走通，再扩大检查范围。每项记录环境、上游 commit、输入、操作、结果和未解决项。

| 检查 | 可观察的通过条件 |
|---|---|
| 部署与复用 | 在目标 Windows 环境启动；完成来源导入、搜索、转换、任务查询及源文件取回；记录容器/数据库等操作负担 |
| Zotero 映射 | 只读导入同一条目两次不重复建身份；保留库 ID、item key、附件和版本关联；确认 Zotero 原库未被修改 |
| 差异能力闭环 | 原文版本 → 一条可定位证据 → 简介 → 一条技术关系 → 人工确认；替换 PDF 后旧证据和确认记录仍指向原版本 |
| 执行与快照 | 沿用既有作业机制，中断并重试不重复提交确认记录；生成快照后继续编辑知识，原快照保持不变 |
| 退出与恢复 | 备份恢复成功；新领域对象、来源映射与证据引用可按版本化 schema 导出并核对；仅复制数据库文件不算跨产品导出 |

缺少技术图界面、页码解析或 PPT 属于正常新增功能，不单独否决基底。只有以下问题经试验确认，才切换到自建轻量工作台：

- 满足版本/确认契约必须大规模改写上游 source/job 的核心读写路径，无法维持清晰扩展边界。
- 正式运行必须长期保留两套权威知识或总任务系统，无法统一责任。
- 目标环境的部署、恢复或数据取回负担超过事先记录的可接受范围，且没有简单的适配办法。

试验失败先记录具体原因和证据，不把一个解析组件失败或一次安装错误等同于架构失败。自建 Vite/FastAPI/SQLite 保留为这些条件下的备选；组件与领域契约尽量可迁移，数据层仍需明确转换，不能声称可以零成本换库。

## 可靠性的边界

采用成熟应用只能复用工程基础，不能保证科研解释正确。证据定位、人工确认、任务幂等、可撤销修订、不可变报告及实测评估仍由本项目补齐。研究论文的原文陈述、系统推导和作者思路假说必须分别标记；引用能打开也不代表它支持该结论。
