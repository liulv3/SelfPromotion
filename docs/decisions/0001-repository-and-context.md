# ADR 0001：单仓库与渐进式项目上下文

状态：已采纳。日期：2026-10-23。

## 背景

首轮输出集中在根目录，后续新会话容易读取大量旧讨论；项目尚未使用 Git。个人科研数据未来会与应用代码共存，需要清楚边界。

## 决定

初始化单一 Git 仓库和 `main`；先提交原始资料再迁移。`AGENTS.md` 是唯一核心说明，`AGENT.md` 仅指向它；详细文档按主题保存，以 `docs/INDEX.md` 按任务路由，`docs/STATUS.md` 只保存当前事实。

代码、开发文档和获准公开样本纳入版本管理。论文原件保持 Zotero；独立个人资料、笔记、数据库、缓存和报告在被忽略的数据/输出目录。维护相对链接、当前决策与历史材料的区别，并用轻量检查脚本验证。

## 代价与未采用方案

增加少量索引维护，但降低每次会话的上下文负担。暂不使用重量文档站、完整 GitFlow、额外项目管理服务或每篇文档一个 Skill。链接不会自动加载，按需读取必须落实为助手工作约定。
